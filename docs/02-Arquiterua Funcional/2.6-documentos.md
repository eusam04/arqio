# 2.6 Módulo de Documentos

## Objetivo

O módulo de documentos será responsável pelo armazenamento, organização e compartilhamento de todos os arquivos relacionados aos projetos.

Seu principal objetivo é garantir que os profissionais tenham acesso à versão correta dos documentos, reduzindo erros durante a execução da obra.

---

## Funcionalidades

O módulo deverá permitir:

- Enviar documentos para um projeto;
- Visualizar documentos;
- Atualizar documentos;
- Excluir documentos;
- Organizar documentos por categorias;
- Pesquisar documentos;
- Baixar documentos;
- Visualizar documentos diretamente na plataforma;
- Controlar quais usuários poderão acessar cada documento.

---

## Categorias de Documentos

Os documentos poderão ser organizados em categorias.

Exemplos:

- Arquitetônico;
- Estrutural;
- Elétrico;
- Hidrossanitário;
- Paisagismo;
- Marcenaria;
- Interiores;
- Orçamento;
- Memorial Descritivo;
- Cronograma.

A empresa poderá criar novas categorias conforme sua necessidade.

---

## Estrutura

Cada projeto possuirá sua própria biblioteca de documentos.

### Exemplo

```text
Casa Panora
│
├── Arquitetônico
│      ├── Planta Baixa.pdf
│      ├── Cortes.pdf
│      └── Fachadas.pdf
│
├── Estrutural
│      ├── Fundação.pdf
│      └── Vigas.pdf
│
├── Elétrico
│
├── Hidrossanitário
│
└── Memorial Descritivo.pdf
```

---

## Informações do Documento

Cada documento poderá possuir informações como:

- Nome;
- Categoria;
- Descrição;
- Data de envio;
- Versão;
- Usuário responsável pelo envio;
- Tamanho do arquivo.

---

## Versionamento

Sempre que um documento for atualizado, o sistema registrará uma nova versão.

Isso permitirá acompanhar o histórico de alterações e evitar que documentos antigos sejam utilizados durante a execução da obra.

Exemplo:

```text
Planta Baixa

Versão 1
Versão 2
Versão 3 (Atual)
```

Apenas a versão mais recente será exibida como padrão, mantendo as anteriores disponíveis para consulta por usuários autorizados.

---

## Visualização

Os documentos poderão ser visualizados diretamente na plataforma, sem necessidade de download.

Arquivos compatíveis poderão ser abertos no navegador.

Caso necessário, o usuário também poderá realizar o download do documento.

---

## Controle de Acesso

Cada documento seguirá as permissões definidas para o projeto e para o usuário.

Exemplo:

- Arquiteto → acesso total;
- Engenheiro → acesso técnico;
- Pedreiro → apenas documentos liberados;
- Cliente → documentos autorizados.

---

## Histórico

Todas as ações relacionadas aos documentos serão registradas.

Exemplos:

- Documento enviado;
- Documento atualizado;
- Documento removido;
- Documento baixado;
- Nova versão criada.

---

## Regras de Negócio

- Todo documento deverá pertencer a um projeto.
- Cada documento deverá possuir uma categoria.
- O sistema deverá manter o histórico de versões.
- Apenas usuários autorizados poderão enviar ou atualizar documentos.
- Documentos antigos não serão excluídos automaticamente quando houver uma nova versão.
- Apenas usuários autorizados poderão visualizar documentos restritos.
