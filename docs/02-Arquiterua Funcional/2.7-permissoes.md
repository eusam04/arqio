# 2.7 Módulo de Permissões

## Objetivo

O módulo de permissões será responsável por controlar o acesso dos usuários às funcionalidades da plataforma.

Seu objetivo é garantir que cada usuário visualize e execute apenas as ações compatíveis com sua função dentro da empresa e do projeto.

---

## Funcionalidades

O módulo deverá permitir:

- Definir funções para os usuários;
- Controlar o acesso aos módulos da plataforma;
- Definir permissões por empresa;
- Definir permissões por projeto;
- Alterar permissões de usuários;
- Restringir ações conforme o perfil do usuário.

---

## Níveis de Acesso

Inicialmente, a plataforma contará com os seguintes perfis:

- Administrador;
- Arquiteto;
- Engenheiro;
- Mestre de Obras;
- Pedreiro;
- Eletricista;
- Encanador;
- Colaborador;
- Cliente.

Novos perfis poderão ser adicionados futuramente.

---

## Permissões por Perfil

Cada perfil possuirá permissões específicas.

### Administrador

- Gerenciar empresa;
- Gerenciar usuários;
- Criar projetos;
- Editar projetos;
- Excluir projetos;
- Gerenciar documentos;
- Gerenciar permissões.

### Arquiteto

- Criar projetos;
- Editar projetos;
- Enviar documentos;
- Atualizar documentos;
- Visualizar documentos;
- Utilizar a IA.

### Engenheiro

- Visualizar documentos;
- Enviar documentos técnicos;
- Atualizar documentos técnicos;
- Utilizar a IA.

### Mestre de Obras

- Visualizar documentos liberados;
- Registrar observações;
- Enviar fotos da obra;
- Utilizar a IA.

### Pedreiro

- Visualizar documentos autorizados;
- Enviar dúvidas;
- Enviar fotos;
- Utilizar a IA.

### Cliente

- Visualizar documentos autorizados;
- Visualizar andamento da obra.

---

## Permissões por Projeto

As permissões poderão variar entre projetos.

Exemplo:

```text
João

Projeto A
→ Arquiteto

Projeto B
→ Cliente
```

Assim, um mesmo usuário poderá exercer funções diferentes em projetos distintos.

---

## Controle de Acesso

Sempre que um usuário tentar acessar uma funcionalidade, o sistema deverá verificar suas permissões.

Caso não possua autorização, o acesso será bloqueado.

---

## Hierarquia

As permissões seguirão uma hierarquia.

```text
Administrador
      │
      ▼
Arquiteto
      │
      ▼
Engenheiro
      │
      ▼
Mestre de Obras
      │
      ▼
Profissionais da Obra
      │
      ▼
Cliente
```

Essa hierarquia servirá apenas como referência para organização dos níveis de acesso.

As permissões poderão ser personalizadas conforme a necessidade da empresa.

---

## Personalização

Empresas poderão personalizar as permissões dos seus usuários.

Exemplos:

- Permitir download de documentos;
- Permitir envio de documentos;
- Permitir exclusão de documentos;
- Permitir gerenciamento da equipe.

---

## Regras de Negócio

- Todo usuário deverá possuir uma função.
- As permissões poderão variar entre projetos.
- Apenas administradores poderão alterar permissões.
- Usuários sem autorização não poderão acessar funcionalidades restritas.
- O sistema deverá validar as permissões antes de cada operação.
