# 2.0 Visão Geral

## Objetivo

Este documento descreve como o Arqio funciona do ponto de vista do usuário, definindo a estrutura da plataforma, os principais módulos e o fluxo de utilização.

Seu objetivo é servir como referência para o desenvolvimento do backend, frontend e banco de dados.

---

## Estrutura Geral

O Arqio é organizado em quatro níveis principais.

```text
Empresa
    │
    ├── Usuários
    │
    ├── Projetos
    │      │
    │      ├── Equipe
    │      ├── Documentos
    │      ├── Comunicação
    │      ├── IA
    │      ├── Fotos
    │      └── Histórico
    │
    ├── Configurações
    │
    └── Assinatura
```
    ---

## Empresa

A empresa representa um escritório de arquitetura, engenharia ou construção.

Cada empresa possui seus próprios:

- Usuários;
- Projetos;
- Configurações;
- Identidade visual;
- Assinatura.

As informações de uma empresa são isoladas das demais.

Isso significa que uma empresa nunca poderá visualizar dados pertencentes a outra.

---

## Usuários

Os usuários representam as pessoas que utilizam a plataforma.

Um usuário poderá:

- Criar uma empresa;
- Ser convidado para uma empresa existente;
- Participar de múltiplas empresas (funcionalidade futura).

Cada usuário possui um perfil de acesso definido pela empresa.

---

## Projetos

O projeto é o núcleo operacional do Arqio.

Todas as informações relacionadas à execução de uma obra estarão vinculadas a um projeto.

Cada projeto poderá conter:

- Documentos;
- Equipe;
- Fotos;
- Comentários;
- Histórico;
- Inteligência artificial.

---

## Fluxo de Entrada

### Primeiro acesso

O usuário realiza seu cadastro utilizando:

- Nome;
- E-mail;
- Senha.

Após confirmar seu cadastro, poderá:

- Criar uma nova empresa;
- Ou aceitar um convite para participar de uma empresa existente.

### Criação de Empresa

Após criar sua conta, o usuário poderá cadastrar sua empresa.

Serão solicitadas inicialmente informações como:

- Nome da empresa;
- Telefone;
- Cidade;
- Estado.

Outras informações poderão ser adicionadas posteriormente.

---

## Convite de Usuários

O administrador poderá convidar novos membros informando o e-mail do usuário.

Após aceitar o convite, o usuário passará a fazer parte da empresa.

---

## Estrutura de um Projeto

Cada projeto possuirá seu próprio ambiente.

### Exemplo

```text
Casa Panora

│

├── Informações Gerais

├── Equipe

├── Documentos

├── Fotos

├── Comunicação

├── IA

└── Histórico
```

### Informações Gerais

Contém os principais dados do projeto.

Nome;
Cliente;
Endereço;
Descrição;
Responsável técnico;
Status.
Equipe

Lista todos os profissionais envolvidos no projeto.

Exemplos
Arquiteto;
Engenheiro;
Mestre de Obras;
Pedreiro;
Eletricista;
Encanador;
Cliente.

Cada profissional possuirá permissões específicas.

### Documentos

Os documentos serão organizados por categorias.

Exemplos
Arquitetônico;
Estrutural;
Elétrico;
Hidrossanitário;
Paisagismo;
Marcenaria.

A empresa poderá criar novas categorias conforme sua necessidade.

### Comunicação

Os membros poderão comentar diretamente dentro do projeto.

Exemplos
Dúvidas;
Observações;
Solicitações;
Respostas.

Todo o histórico ficará registrado.

### Inteligência Artificial

O Arqio possuirá um assistente virtual chamado Airo.

Inicialmente, o Airo responderá perguntas gerais.

No futuro, poderá utilizar os documentos do projeto como base para responder dúvidas específicas.

### Histórico

Todas as ações importantes serão registradas.

Exemplos
Documento enviado;
Documento atualizado;
Usuário convidado;
Usuário removido;
Projeto arquivado.
Controle de Permissões

> Cada empresa definirá quais usuários podem acessar determinadas funcionalidades.

### Exemplos

Administrador

Acesso total.

Arquiteto

Gerenciamento de projetos.

Engenheiro

Acesso técnico.

Pedreiro

Consulta aos documentos liberados.

Cliente

Visualização limitada.
Princípios da Plataforma

> O desenvolvimento do Arqio seguirá os seguintes princípios:

Simplicidade;
Organização;
Segurança;
Escalabilidade;
Colaboração;
Facilidade de uso.
