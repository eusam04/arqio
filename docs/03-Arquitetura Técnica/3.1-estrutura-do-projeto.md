# 3.1 Estrutura do Projeto

## Objetivo

Este documento define a organização das pastas e arquivos do Arqio.

Seu objetivo é manter o projeto organizado, facilitar a manutenção do código e permitir que novas funcionalidades sejam adicionadas de forma simples e escalável.

---

## Estrutura Geral

O projeto será dividido em três partes principais.

```text
Arqio
│
├── backend
│
├── frontend
│
└── docs
```

Cada pasta terá uma responsabilidade específica.

---

## Backend

O backend será responsável pela lógica de negócio da plataforma e pela comunicação com o banco de dados.

Estrutura inicial:

```text
backend
│
├── src
│   │
│   ├── config
│   ├── controllers
│   ├── middlewares
│   ├── models
│   ├── routes
│   ├── services
│   ├── repositories
│   ├── utils
│   ├── types
│   ├── app.ts
│   └── server.ts
│
├── .env
├── package.json
└── tsconfig.json
```

---

---

## Documentação

Toda a documentação da plataforma ficará organizada na pasta `docs`.

Exemplo:

```text
docs
│
├── 01-visao-do-produto.md
├── 02-Arquitetura Funcional
├── 03-Arquitetura Tecnica
└── futuras-versoes.md
```

---

## Organização

Cada camada da aplicação será independente.

- O frontend será responsável apenas pela interface.
- O backend será responsável pelas regras de negócio.
- O banco de dados armazenará as informações da plataforma.

Essa separação facilita a manutenção, os testes e a evolução do sistema.

---

## Padrões

Durante o desenvolvimento serão adotados os seguintes padrões:

- Organização por responsabilidade;
- Código modular;
- Separação entre regras de negócio e acesso ao banco de dados;
- Reutilização de componentes;
- Tipagem com TypeScript.
