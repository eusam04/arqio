# 3.9 Implantação e Hospedagem

## Objetivo

Este documento define as diretrizes para executar, publicar e manter o Arqio disponível nos ambientes de desenvolvimento e produção.

O objetivo é estabelecer uma estrutura de hospedagem que permita disponibilizar o sistema com segurança, facilitar sua manutenção e manter os serviços necessários ao funcionamento da aplicação.

---

## Ambientes de Execução

O Arqio utilizará dois ambientes principais.

### Desenvolvimento local

Será utilizado durante a implementação e os testes realizados na máquina do desenvolvedor.

Nesse ambiente:

- O frontend e o backend poderão ser executados localmente;
- O banco de dados poderá utilizar uma instância local ou um serviço remoto de desenvolvimento;
- As configurações serão definidas por variáveis de ambiente;
- As alterações serão verificadas antes de serem publicadas.

### Produção

Será utilizado pelos usuários finais.

Nesse ambiente:

- O frontend ficará disponível por meio de um endereço público;
- O backend será hospedado em um serviço capaz de executar a aplicação Node.js;
- O banco de dados será disponibilizado por um serviço apropriado;
- As conexões públicas utilizarão HTTPS;
- As credenciais serão configuradas de maneira segura;
- A aplicação deverá tratar falhas e indisponibilidades adequadamente.

As configurações de produção serão independentes das configurações utilizadas no desenvolvimento local.

---

## Estrutura de Hospedagem

A arquitetura de produção será composta por três partes principais.

### Frontend

O frontend, desenvolvido com React, TypeScript e Vite, será preparado para produção por meio do processo de build do Vite.

Os arquivos gerados serão publicados em um serviço de hospedagem compatível com aplicações web estáticas.

A plataforma deverá permitir configurar o endereço público da API e disponibilizar a interface por HTTPS.

### Backend

O backend, desenvolvido com Node.js, Express e TypeScript, será executado em um serviço de hospedagem compatível com aplicações Node.js.

O serviço deverá permitir:

- Configuração de variáveis de ambiente;
- Execução do servidor;
- Comunicação com o MongoDB;
- Disponibilização dos endpoints da API;
- Consulta de logs para investigar erros;
- Reinicialização e atualização da aplicação.

### Banco de Dados

O MongoDB será utilizado para armazenar os dados persistentes do Arqio.

Em produção, será priorizado um serviço de banco de dados gerenciado, com mecanismos apropriados de autenticação, controle de acesso, backup e recuperação.

O banco de dados não deverá ficar diretamente exposto ao público sem os controles de segurança necessários.

---

## Serviços de Hospedagem

As plataformas específicas serão escolhidas durante a implantação, considerando custo, facilidade de configuração, disponibilidade e compatibilidade com a aplicação.

As opções inicialmente consideradas são:

- **Frontend:** Vercel ou serviço equivalente;
- **Backend:** Render, Railway ou serviço equivalente;
- **Banco de dados:** MongoDB Atlas.

Essas opções são referências iniciais, não decisões definitivas. A escolha deverá considerar os planos disponíveis e os custos vigentes no momento da implantação.

---

## Processo de Publicação

A publicação deverá seguir um fluxo organizado:

1. Desenvolver a funcionalidade no ambiente local.
2. Executar os testes disponíveis.
3. Verificar se o código está consistente com a arquitetura definida.
4. Registrar as alterações no Git.
5. Enviar as alterações para o repositório remoto.
6. Executar o processo de build ou implantação conforme o serviço configurado.
7. Verificar se a aplicação está funcionando no ambiente publicado.

Quando a integração contínua estiver configurada, parte dessas etapas poderá ser executada automaticamente.

---

## Integração com o GitHub

O GitHub será utilizado para armazenar o código-fonte e manter o histórico de alterações.

O repositório servirá como base para a publicação da aplicação nos serviços de hospedagem.

O fluxo de desenvolvimento deverá preservar commits descritivos e evitar publicar alterações que ainda não tenham sido verificadas.

A configuração de implantação automática dependerá da integração entre o repositório e os serviços escolhidos.

---

## Variáveis de Ambiente

Cada serviço deverá possuir suas próprias configurações.

O frontend deverá receber o endereço público da API.

O backend deverá receber as configurações necessárias para executar o servidor, conectar-se ao MongoDB e utilizar os serviços integrados.

As variáveis de ambiente deverão ser configuradas diretamente nos serviços de hospedagem quando houver suporte a esse recurso.

Segredos, senhas e credenciais não deverão ser incluídos no repositório Git ou nos arquivos públicos do frontend.

As regras detalhadas estão definidas no documento `3.6-configuracao-de-ambiente.md`.

---

## Domínio e HTTPS

O Arqio deverá utilizar HTTPS em produção para proteger a comunicação entre o navegador e os serviços da aplicação.

Inicialmente, poderão ser utilizados os endereços fornecidos pelas plataformas de hospedagem.

A configuração de um domínio próprio poderá ser realizada quando houver necessidade e disponibilidade.

O endereço do frontend, o endereço da API e as regras de CORS deverão ser configurados de forma compatível.

---

## Arquivos e Armazenamento

Os documentos enviados pelos usuários serão armazenados em um serviço próprio de armazenamento de arquivos, separado do banco de dados.

A implantação deverá garantir que o backend possua as credenciais necessárias para acessar esse serviço sem expô-las ao frontend.

O armazenamento deverá respeitar as permissões de acesso, o isolamento entre empresas e as regras de versionamento definidas no documento `3.7-armazenamento-de-arquivos.md`.

---

## Monitoramento e Logs

A aplicação deverá permitir identificar erros e problemas operacionais.

O backend deverá registrar informações técnicas relevantes, como falhas inesperadas e erros de comunicação com serviços externos.

Os logs não deverão conter senhas, tokens secretos, credenciais ou dados pessoais desnecessários.

Os serviços de hospedagem poderão fornecer registros de execução e informações sobre a disponibilidade da aplicação.

A estrutura de monitoramento poderá ser ampliada conforme as necessidades do sistema.

---

## Backup e Recuperação

O ambiente de produção deverá utilizar mecanismos de backup adequados para os dados persistentes.

A estratégia deverá considerar:

- Frequência dos backups;
- Proteção das cópias de segurança;
- Retenção dos dados;
- Procedimentos de recuperação;
- Necessidade de preservar documentos armazenados externamente ao MongoDB.

A existência de backups deverá ser acompanhada de verificações que permitam avaliar se os dados podem ser recuperados.

As configurações definitivas dependerão dos serviços escolhidos e dos requisitos operacionais do Arqio.

---

## Segurança na Implantação

A implantação deverá seguir estas diretrizes:

- Utilizar HTTPS em produção;
- Manter credenciais fora do código-fonte;
- Restringir o acesso administrativo aos serviços;
- Configurar o banco de dados com autenticação;
- Permitir somente as conexões necessárias;
- Configurar CORS para as origens autorizadas;
- Evitar disponibilizar arquivos privados publicamente;
- Manter as dependências atualizadas;
- Verificar os logs após alterações importantes;
- Testar as funcionalidades essenciais após cada publicação.

---

## Critérios para Publicação

Uma versão poderá ser publicada quando:

- O build for concluído com sucesso;
- Os testes disponíveis forem executados;
- As variáveis necessárias estiverem configuradas;
- A conexão com o banco de dados estiver funcionando;
- As rotas essenciais da API estiverem disponíveis;
- As regras de autenticação e autorização estiverem aplicadas;
- Os principais fluxos da aplicação forem verificados no ambiente publicado.

A publicação deverá ser acompanhada de uma verificação básica de funcionamento.
