# 3.6 Configuração de Ambiente e Variáveis de Ambiente

## Objetivo

Este documento define como as configurações da aplicação Arqio serão organizadas para os ambientes de desenvolvimento e produção.

O objetivo é separar as configurações do código-fonte, proteger informações sensíveis e facilitar a execução da aplicação em diferentes ambientes.

---

## Ambientes da Aplicação

O Arqio utilizará dois ambientes principais durante o desenvolvimento inicial.

### Desenvolvimento

Ambiente utilizado para desenvolver, executar e testar a aplicação localmente.

Características:

- Execução na máquina do desenvolvedor;
- Utilização de serviços e bancos de dados destinados ao desenvolvimento;
- Configurações específicas para testes locais;
- Mensagens de erro que auxiliem na identificação de problemas, sem expor segredos.

### Produção

Ambiente utilizado pelos usuários finais.

Características:

- Aplicação hospedada em serviços apropriados;
- Comunicação HTTPS;
- Credenciais e configurações próprias;
- Proteção das informações sensíveis;
- Tratamento de erros sem exposição de detalhes internos.

As configurações dos dois ambientes deverão ser independentes.

---

## Variáveis de Ambiente

As variáveis de ambiente permitirão definir configurações sem precisar inserir seus valores diretamente no código-fonte.

No backend, elas poderão ser acessadas por meio de `process.env`.

A biblioteca `dotenv` poderá ser utilizada para carregar variáveis de um arquivo `.env` durante o desenvolvimento local.

Em produção, as variáveis deverão ser configuradas diretamente no ambiente de hospedagem, sempre que o serviço oferecer esse recurso.

---

## Variáveis do Backend

O backend deverá prever as seguintes configurações:

| Variável | Finalidade |
|---|---|
| `PORT` | Porta utilizada pelo servidor |
| `NODE_ENV` | Ambiente de execução |
| `MONGODB_URI` | Endereço de conexão com o MongoDB |
| `JWT_SECRET` | Segredo utilizado na assinatura dos tokens JWT, caso seja adotado um algoritmo que utilize segredo compartilhado |
| `JWT_EXPIRES_IN` | Prazo de validade dos tokens |
| `FRONTEND_URL` | Origem autorizada do frontend |
| `BCRYPT_SALT_ROUNDS` | Custo utilizado na geração dos hashes de senha, caso essa configuração seja adotada |

As variáveis necessárias serão definidas durante a implementação de cada funcionalidade.

Caso seja utilizada outra estratégia de autenticação ou assinatura de tokens, as configurações correspondentes deverão ser ajustadas.

---

## Variáveis do Frontend

O frontend poderá utilizar variáveis de ambiente para configurações públicas necessárias à execução da interface.

Exemplo:

| Variável | Finalidade |
|---|---|
| `VITE_API_URL` | Endereço base da API do Arqio |

No Vite, as variáveis disponibilizadas ao frontend por meio do prefixo `VITE_` poderão ser incluídas no código entregue ao navegador.

Por esse motivo, elas deverão conter somente informações públicas.

**Segredos, senhas, tokens privados e credenciais de serviços nunca deverão ser colocados em variáveis `VITE_`.**

---

## Arquivo `.env`

Durante o desenvolvimento local, o backend poderá utilizar um arquivo `.env` para armazenar as configurações necessárias.

Exemplo ilustrativo:

```env
PORT=3000
NODE_ENV=development
MONGODB_URI=mongodb://localhost:27017/arqio
JWT_SECRET=SUBSTITUIR_POR_UM_SEGREDO_LOCAL
JWT_EXPIRES_IN=15m
FRONTEND_URL=http://localhost:5173
BCRYPT_SALT_ROUNDS=12
```

Os valores apresentados são exemplos de configuração. O segredo JWT deverá ser substituído por um valor forte e exclusivo antes da execução da autenticação.

O endereço do MongoDB deverá corresponder à configuração efetivamente utilizada no ambiente local.

O prazo de validade do token é uma decisão inicial de projeto e poderá ser ajustado durante a implementação da estratégia de sessão.

---

## Arquivo `.env.example`

O projeto deverá possuir um arquivo `.env.example` contendo os nomes das variáveis necessárias, mas sem credenciais reais.

Exemplo:

```env
PORT=3000
NODE_ENV=development
MONGODB_URI=
JWT_SECRET=
JWT_EXPIRES_IN=15m
FRONTEND_URL=http://localhost:5173
BCRYPT_SALT_ROUNDS=12
```

Esse arquivo servirá como referência para configurar o ambiente de desenvolvimento.

O `.env.example` poderá ser versionado no Git porque não deverá conter segredos ou credenciais reais.

O arquivo `.env` com valores locais deverá permanecer fora do controle de versão.

---

## Proteção de Segredos

As seguintes regras deverão ser respeitadas:

- Não versionar arquivos `.env` com valores secretos.
- Não publicar credenciais do banco de dados.
- Não incluir segredos diretamente no código-fonte.
- Não compartilhar tokens privados em mensagens ou capturas de tela.
- Não registrar senhas ou segredos em logs.
- Utilizar credenciais diferentes para desenvolvimento e produção.
- Restringir o acesso às configurações de produção.
- Substituir credenciais imediatamente caso sejam expostas.

O `.gitignore` deverá incluir os arquivos de ambiente privados, preservando os arquivos de exemplo.

---

## Validação das Configurações

O backend deverá verificar se as variáveis obrigatórias estão disponíveis durante sua inicialização.

Caso uma configuração essencial esteja ausente ou inválida, o servidor deverá apresentar uma mensagem de erro clara no ambiente de desenvolvimento e interromper a inicialização quando necessário.

Essa validação evitará que a aplicação seja executada com configurações incompletas.

Valores secretos nunca deverão ser incluídos nas mensagens de erro.

---

## Conexão com o Banco de Dados

A conexão com o MongoDB deverá utilizar a variável `MONGODB_URI`.

O endereço poderá apontar para uma instância local durante o desenvolvimento ou para um serviço hospedado em outro ambiente.

A aplicação deverá tratar falhas de conexão adequadamente e evitar iniciar operações que dependam do banco de dados quando a conexão não estiver disponível.

As credenciais utilizadas na conexão deverão ser protegidas.

---

## Configuração de Produção

Em produção:

- As variáveis deverão ser configuradas no serviço de hospedagem.
- O banco de dados deverá utilizar credenciais apropriadas.
- A conexão deverá ser protegida.
- O frontend deverá utilizar o endereço público correto da API.
- O backend deverá aceitar solicitações somente das origens autorizadas quando o CORS estiver configurado.
- Os segredos deverão ser mantidos fora do código-fonte e dos arquivos públicos.
- Os logs não deverão expor informações sensíveis.

A configuração específica dependerá dos serviços de hospedagem escolhidos para o Arqio.

---

## Responsabilidades

### Backend

- Ler e validar as variáveis necessárias;
- Carregar o `.env` no desenvolvimento, quando aplicável;
- Proteger credenciais;
- Configurar a conexão com o banco de dados;
- Utilizar configurações adequadas a cada ambiente.

### Frontend

- Utilizar variáveis públicas para acessar a API;
- Não armazenar segredos no código entregue ao navegador;
- Permitir a configuração do endereço da API por ambiente.

### Git

- Ignorar arquivos de ambiente privados;
- Manter um `.env.example` sem credenciais reais;
- Evitar o versionamento acidental de segredos.
